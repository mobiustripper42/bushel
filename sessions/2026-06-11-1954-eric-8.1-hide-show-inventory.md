## Task 2: Reject orders against sold-out (qty=0) products (#132, DEC-036)

**Completed:**
- Root-caused: not a UI bug. Client is safe at load (`perUnitMax=0` → `clamp` pins stepper to 0). The incident was the stale-tab race + a missing server guard — `place_order` applied DEC-012 optimistic decrement even at qty=0, driving it negative.
- Migration `supabase/migrations/20260611213000_place_order_reject_soldout.sql`: decrement → `UPDATE products … WHERE id=? AND qty_available > 0` + `IF NOT FOUND THEN RAISE … sold out`. Atomic/race-free; raise rolls back the whole order. DEC-012 last-few oversell (qty>0) unchanged.
- `place-order.ts`: maps the raise to a friendly reload message.
- pgTAP `place_order_units.sql`: sold-out rejection (stays 0, no order row) + multi-item atomicity (in-stock line rolls back when a later line is sold out). 143 pgTAP pass.
- Playwright `customer-closed-and-soldout.spec.ts`: sold-out mid-order race. DEC-036 in DECISIONS.md.
