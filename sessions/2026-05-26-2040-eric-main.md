## Task 1: Inventory qty input — accept fractional values

**Completed:**
- `src/components/admin/inventory-row.tsx` — qty input flipped from `parseInt + inputMode="numeric"` to the same decimal draft pattern the units drawer already uses (`parseFloat + inputMode="decimal"`), rounds to 2dp on save to match the `numeric(10,2)` DB column. Without this, every multi-unit order that left a fractional remainder (e.g. half-pound unit consumes 0.5 base lb, qty_available becomes `2.5`) silently lost the fraction on Annabel's next save.
- `src/actions/save-inventory.ts` — server validator relaxed from `Number.isInteger` to `Number.isFinite`; matching 2dp rounding on store as defense in depth. The pre-existing DEC-012 comment ("qty allows negatives — admin must be able to record oversold by direct entry") was aspirational; client validator was stricter than server. Code review caught this asymmetry and `7238ce0` resolved by dropping the client's `v >= 0` guard on qty to match. Price + conv keep `>= 0` (no semantic meaning for negatives there).
