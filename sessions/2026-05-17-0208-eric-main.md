**Snags worth remembering:**
- **CSS cascade collision with same-specificity selectors.** First attempt put `.ord-*` mobile rules inside the existing `@media (max-width: 640px)` block at line 2014, but the base `.ord-*` rules sit at line 2150+ — same specificity, later source order, so the base rules won the cascade. The detail-grid stayed two columns at 375px until I moved the mobile block to the END of the file. Lesson: `@media` doesn't bump specificity; if you can't reorder, you need a stricter selector or `!important`. Reorder is cleaner. Two `@media (max-width: 640px)` blocks now exist (one at 2014 for `.send-*`, one at the end for `.ord-*`) — disjoint selectors, no harm, but worth a note if a third page tempts consolidation.
- **Stale `next start` on port 3001 — `lsof` empty but `ss -tlnp` saw it.** CLAUDE.md already documents this; caught it immediately this time because session 26's snag was top-of-mind. `ss -tlnp 2>/dev/null | grep :3001` is the reliable check.
- **Sort UI is desktop-only on this page.** When `<thead>` is `display: none` at mobile width, the existing "sort by Total/Customer" tests time out trying to click the hidden header buttons. Both `admin-orders.spec.ts` and `orders-flow.spec.ts` had sort-driven pin tests; both now `test.skip(testInfo.project.name === "mobile", ...)`. The pin behavior at 375px is covered by the new admin-orders mobile test (uses default placed-desc order with a flagged-and-clean pair, asserts the flagged card is first).
