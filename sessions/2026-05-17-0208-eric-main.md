## Task 2: Phase 6.6 — /admin/inventory + /admin/customers mobile-responsive (#111)

**Completed:**
- `src/styles/app.css` — new `@media (max-width: 640px)` block at end of file with `.data-row` flex-column card-stack (inventory) and `.cust-row` grid-area card-stack (customers). - `tests/admin-inventory.spec.ts` — mobile-only fit-to-viewport + qty-edit smoke.
- `tests/admin-customers.spec.ts` — mobile-only fit-to-viewport + copy-link reachability smoke. - `playwright.config.ts` — drops `admin-inventory.spec.ts` + `admin-customers.spec.ts` from mobile testIgnore.

**Snags worth remembering:**
- **CSS-grid `grid-template-columns: 1fr auto auto` collapses 1fr to 0px when auto-sized columns hit input intrinsic widths.** First attempt at inventory used a 3-column grid with grid-template-areas. The auto columns (switch ~90px, trash ~40px) plus inputs in the auto columns of OTHER rows (unit input ~140px, qty ~140px) made auto columns sum to ~280px in a 343px content area, leaving 1fr at zero. Diagnosed via a `getBoundingClientRect` dump showing the name td at width 0, height 88 (i.e., child rendered but cell collapsed). Switched to `display: flex; flex-direction: column` for inventory — taller cards but every input is full-width and reachable. The customers grid layout works because its auto column (Switch) is small and the 1fr column carries text content rather than inputs.
- **Mobile WebKit server-action races `page.reload()` more aggressively than desktop Chrome.** The "subscribed switch toggles" test was deflakily fixed by `await expect.poll(...).toBe(expectedFlipped)` against the DB before reloading. The pattern matches `advanceOrderStatus` polling from session 25/26 — Phase 6 admin tests with useTransition + `router.refresh()` + `page.reload()` should default to a DB poll between the action and the reload on mobile WebKit.
- **`:has(.data-table)` / `:has(.cust-table)` scoping is fine at this project's scale.** Modern WebKit + Chromium support it; the alternative would be a body-class on each admin page. If another admin page ever embeds a `.data-table` in `<main>`, its padding silently flips to 16px on mobile — accept the trade-off until it bites.
- **Inline `style={{ width: 90 }}` on inventory row tds forced eight `!important` rules.** Annoying but not load-bearing. Code review flagged: lift those inline widths to a `.col-i-*` class on the next inventory touch and the `!important` chain disappears. Also `nth-child(7)`/`(8)` is fragile if anyone adds/removes a `<td>` in inventory-row.tsx; classes would fix both issues.
- **"Just works" is a real spec.** User explicitly said Annabel uses production from desktop; mobile is the back-pocket case. Pulled in a `:has()`-scoped @media block, accepted taller cards from the flex pivot, accepted two non-blocking cleanup items. Shipping at the stated bar instead of grinding on polish was the right call.
