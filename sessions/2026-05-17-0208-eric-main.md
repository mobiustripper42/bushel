**Snags worth remembering:**

Diagnosed via a `getBoundingClientRect` dump showing the name td at width 0, height 88 (i.e., child rendered but cell collapsed). The pattern matches `advanceOrderStatus` polling from session 25/26 — Phase 6 admin tests with useTransition + `router.refresh()` + `page.reload()` should default to a DB poll between the action and the reload on mobile WebKit.

## Task 3: Phase 6.7 — Desktop SMS relay via clipboard + Messages for Web (#112)

**Completed:**
- `src/components/admin/send-row.tsx` — added `isDesktopOperator()` using `window.matchMedia("(pointer: fine)").matches`. On desktop, click handler `preventDefault`s the `sms:` nav, opens `https://messages.google.com/web/conversations` in a new tab synchronously (before any await), then `navigator.clipboard.writeText(body)`, then sets a 2.4s "Copied — paste in Messages" indicator, then `recordOptimistic()`. Mobile path unchanged.
- `src/styles/app.css` — `.send-row-copied` style (small green text alongside the existing `.send-row-error`).
- `tests/admin-send.spec.ts` — new desktop test grants clipboard perms, listens for popup, asserts clipboard content matches the row's sms-body, popup URL contains `messages.google.com`, Copied indicator visible, Sent pill flips, DB row persisted. `beforeEach` grants clipboard permissions on chromium only (WebKit rejects the permission name).
- `tests/notifications-flow.spec.ts` — same chromium-only clipboard grant in beforeEach (existing tests now hit the desktop branch).

**Snags worth remembering:**
- **Clipboard failure used to silently record the send.** First-pass commit had `try { await writeText } catch { setError } window.open + recordOptimistic`. Code-review flagged that the error path still recorded — operator would see red error + green Sent pill simultaneously. Fixed: `catch` now `return`s before `recordOptimistic()`. Lesson: when a click handler does multiple side effects, every failure branch needs to decide which subsequent effects still make sense — defaulting to "fall through" is what produced the contradictory state.
- **`window.open` after `await` is popup-blocker bait on Safari.** Code-review flagged: Safari (and some Chromium variants) treat post-await `window.open` as non-user-initiated. Moved the open call to fire synchronously inside the click handler before the clipboard await. Worth a CLAUDE.md note: any click handler that mixes `await` + `window.open` should hoist the window.open above the await.
- **Pre-existing tests broke because the desktop branch now requires clipboard perms.** Three tests in admin-send.spec.ts and three in notifications-flow.spec.ts click Send and assert the Sent pill flip. Before 6.7, click → sms: nav silently ignored by headless Chromium → recordOptimistic still runs → pill flips. After 6.7, click → desktop branch → clipboard write throws (no perm) → early return → pill does NOT flip. Fix: `test.beforeEach(async ({ context, browserName }) => { if (browserName === "chromium") await context.grantPermissions(["clipboard-read", "clipboard-write"]); })`. WebKit rejects the permission name; mobile project doesn't need it (sms: branch).
- **`test.use({ permissions: [...] })` at describe-level errors on WebKit.** First attempt used describe-level `test.use({ permissions: ["clipboard-read", "clipboard-write"] })`, which Playwright applies to ALL projects including the WebKit mobile project. WebKit threw `Unknown permission: clipboard-write` before any test ran. Per-test `context.grantPermissions` inside a `browserName === "chromium"` guard is the workaround.

**Code review:** Two real findings addressed before opening the PR (clipboard-fail-records-send bug + popup-blocker risk on Safari). Plus a comment placement nit and a test-skip clarification. PR opened post-fix.
