**Snags worth remembering:**
- Apex's `/apple-touch-icon.png`, `/icon-192.png`, `/icon-512.png`, `/icon.png`, `/apple-icon.png` all return 200 with the same etag — but they're Netlify SPA fallbacks serving HTML, not real images. Only `/favicon.png` is a real asset. Confirmed via hexdump: real PNG starts with `89 50 4e 47`, the fallback starts with `<!DOCTYPE html`. Headers alone (`content-type: image/png` was missing on the fallbacks) would have flagged this earlier — worth checking content-type *and* magic bytes when scraping assets.
- `pkill -f "next start"` does not reach the `next-server` worker. The kill chain that actually works: `kill $(lsof -ti:3001)`. Same gotcha as last task — calling out twice means it goes in the playbook.
- Next.js cached the old favicon.ico in `.next/server/app/` from a prior build even after the source was deleted. `rm -rf .next` + rebuild was needed to flush. Stale-build symptoms (favicon.ico still 200, icon.png 404, head still references the hashed default) survived multiple server restarts until the build cache was cleared.

**Code review:** 2 cleanup nits, both deferred — duplicate PNG bytes are unavoidable by App Router convention; unoptimized 63KB-each is fine for a cosmetic ship (pngquant pass would cut to 8–15KB if we revisit).
