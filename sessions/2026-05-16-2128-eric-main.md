**Snags worth remembering:**
- **Stacked PRs collapse silently if the bottom of the stack merges before the rest.** Last session's "Stacking PRs is preferred" lesson (from CLAUDE.md) needs a footnote: GitHub does not auto-rebase the stack when the bottom merges. Each downstream PR's `baseRefName` stays pointed at the old (now-orphaned) task branch, and clicking "Merge" on GitHub's UI merges into that detached branch. Always re-base downstream PRs onto main between merges, OR merge bottom-up and watch for each PR's base auto-flipping to main after the prior one merges (the auto-flip behavior is unreliable).
