**Snags worth remembering:**
- **Stacked PRs collapse silently if the bottom of the stack merges before the rest.** Last session's "Stacking PRs is preferred" lesson (from CLAUDE.md) needs a footnote: GitHub does not auto-rebase the stack when the bottom merges. Each downstream PR's `baseRefName` stays pointed at the old (now-orphaned) task branch, and clicking "Merge" on GitHub's UI merges into that detached branch. Always re-base downstream PRs onto main between merges, OR merge bottom-up and watch for each PR's base auto-flipping to main after the prior one merges (the auto-flip behavior is unreliable). Worth a DEC entry or a CLAUDE.md addendum.
- **`/retro` doesn't verify tag trees.** It assumed each merged PR landed on main and bumped versions accordingly. A `/retro` Step 8.x check — "for each PR in the phase, verify `gh pr view <N> --json baseRefName | jq` equals `main`/`staging`" — would have caught this in real time. Surface for `read-the-tape` / seeds backport.

CI handles this in `.github/workflows`. Worth adding `webServer` to `playwright.config.ts` for local-loop ergonomics (separate Phase 6 task).
