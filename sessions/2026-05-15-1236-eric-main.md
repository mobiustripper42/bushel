## Task 1: Phase 4.1 — `sms:` deep-link builder utility (#87)

**Completed:**
- `src/lib/notifications/sms-deep-link.ts`: pure-function `buildSmsUrl({ phone, body })` + `normalizePhone(raw)`. RFC 5724 form `sms:NUMBER?body=...`. Never-throws, always emits `?body=` for stable caller shape (4.2 consumes). `encodeURIComponent` for the body covers spaces (`%20`), newlines (`%0A`), reserved chars (`&?=#+/`), and multi-byte emoji.
- `normalizePhone`: `trim()` once; preserve a leading `+`; strip all other non-digit chars. Interior `+` is intentionally stripped (locked by test). Extension syntax (`x123`) glues onto the main number — pinned by a test as known V1 behavior, not silently undefined.
- `tests/sms-deep-link.spec.ts`: 13 unit-style Playwright tests (no `page`, pure-function assertions). Bushel has no vitest/jest; Playwright `test()` blocks are the only test harness, fine for a 2-pt lib (DEC-023 light unit / heavy integration). 13/13 green on desktop.
- No DB, no UI, no auth, no consumer wiring — that's 4.2's scope. `design/admin-send.{jsx,css}` left untouched.
